Zero-Secret AWS Deployments with GitHub Actions & OpenID Connect (OIDC)

Storing long-lived AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY inside GitHub repository secrets is a major security vulnerability. By configuring AWS IAM Identity Providers with GitHub's OIDC token issuer, our workflows request short-lived (15-minute) STS credentials tied strictly to the repository and branch name.

// GitHub Actions Security Flow:
GitHub Runner → OIDC JWT Token → AWS STS AssumeRoleWithWebIdentity → Temporary Credentials → EC2 Zero-Downtime Deploy

Architecture • November 2025 • 7 min read

Designing Modular Monoliths in Laravel: High Growth Without Microservices Complexity

Premature microservices often kill early-stage velocity with network latency, distributed transactions, and deployment overhead. By organizing Laravel applications into self-contained Domain Modules (e.g. app/Modules/Billing, app/Modules/Identity) with strict internal contracts, you get all the benefits of clean code boundaries while maintaining single-deploy simplicity.

// Architecture Principles:
1. Domain Modules own their migrations, routes, DTOs, and event listeners.
2. Cross-domain interactions occur strictly via Interfaces & Event Dispatches (no cross-module direct model coupling).

Preventing Concurrency Race Conditions and Double-Spending with Redis Atomic Locks

When multiple webhook calls or simultaneous user clicks hit an account balance or inventory check at the same millisecond, simple database checks fail due to read-uncommitted race conditions. We implement Redis atomic locks (Cache::lock()) paired with database row-level locking (SELECT ... FOR UPDATE) and idempotent transaction tokens to guarantee 100% financial correctness.

// Implementation Pattern:
$lock = Cache::lock("wallet:{$userId}", 10);
if ($lock->get()) { DB::transaction(fn() => ...); $lock->release(); }
